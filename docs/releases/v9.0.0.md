# Release v9.0.0 - DevSecOps Scanning and Dependency Governance

Release date: 2026-06-01

V9 adds DevSecOps scanning and dependency governance to the AWS EKS Platform
Golden Path.

The goal of this release is to make security and dependency updates visible
through CI and pull requests.

## Highlights

V9 adds:

- Trivy filesystem scan in Platform CI
- high and critical vulnerability gate
- Dependabot configuration
- GitHub Actions dependency monitoring
- Python dependency monitoring
- Terraform dependency monitoring
- Docker base image monitoring
- documented Dependabot PR workflow

## Platform CI security scan

Platform CI now includes a dedicated security job.

The job uses:

```text
aquasecurity/trivy-action
```

Current policy:

```text
scan-type: fs
severity: CRITICAL,HIGH
ignore-unfixed: true
exit-code: 1
```

This makes the CI fail when fixed high or critical vulnerabilities are found.

## Dependabot configuration

V9 adds:

```text
.github/dependabot.yml
```

Dependabot monitors:

- GitHub Actions
- Python dependencies under `apps/incident-api`
- Terraform dependencies under `terraform/environments/dev`
- Docker dependencies under `apps/incident-api`

## Validation

Dependabot opened multiple pull requests after the configuration was added.

The PRs were reviewed and merged only after CI passed.

Some PRs initially failed because they were created before the Trivy workflow
action reference was fixed.

Those branches were updated with the latest `main`, then CI was rerun by
pushing the updated PR branches.

## Dependency update workflow

The validated workflow is:

```text
Dependabot opens pull request
-> Platform CI runs
-> update branch if needed
-> review changed files
-> merge only if checks pass
-> pull latest main locally
```

This keeps dependency updates controlled instead of automatic and blind.

## Security and governance impact

V9 improves the platform by making security drift visible.

It reinforces these principles:

- dependencies should be tracked explicitly
- security checks should run before merge
- dependency updates should be reviewed
- CI should block important fixed vulnerabilities
- DevSecOps controls should not require a live EKS cluster

## Current limitations

V9 does not include:

- SBOM generation
- image signing
- Cosign
- SLSA provenance
- Kyverno
- OPA Gatekeeper
- admission control policies
- runtime threat detection

These remain future DevSecOps enhancements.

## Final outcome

V9 adds a practical DevSecOps loop:

```text
repository scan
-> dependency monitoring
-> pull request validation
-> CI security gate
-> reviewed merge
```
