# Release v8.0.0 - FinOps and Cleanup Governance

Release date: 2026-06-01

V8 adds FinOps and cleanup governance to the AWS EKS Platform Golden Path.

The goal of this release is to make cost control explicit, repeatable, and
verifiable after each temporary AWS validation session.

## Highlights

V8 adds:

- AWS cleanup verification script
- FinOps cost-control runbook
- post-destroy validation process
- explicit cost-driver documentation
- cleanup criteria for EKS sessions
- ECR image cleanup awareness
- manual verification commands for AWS resources

## Cleanup verification script

V8 adds:

```text
scripts/check-aws-cleanup.sh
```

The script verifies that common AWS cost drivers are absent after cleanup.

It checks:

- EKS cluster
- Elastic LoadBalancers
- NAT Gateways
- EC2 instances
- unattached EBS volumes
- Elastic IPs
- ECR image state

## Script behavior

The script is intentionally strict.

If an expensive resource is still present, the script fails instead of
silently passing.

Example validation while the EKS cluster is still active:

```text
[FAIL] EKS cluster still exists: aws-eks-platform-golden-path-dev-eks
```

This confirms that the script detects incomplete cleanup correctly.

## Usage

Run the script after `terraform destroy`.

```bash
AWS_PROFILE=tf-eks-golden-path \
AWS_REGION=eu-west-3 \
./scripts/check-aws-cleanup.sh
```

The expected final result after a successful cleanup is:

```text
[PASS] AWS cleanup verification completed successfully
```

## Main cost drivers

The main resources tracked by V8 are:

| Resource | Cost risk |
| --- | --- |
| EKS cluster | hourly control plane cost |
| EC2 worker nodes | compute cost while running |
| EBS volumes | storage cost if left unattached |
| LoadBalancers | hourly and traffic cost |
| NAT Gateways | high hourly and data processing cost |
| Elastic IPs | cost if allocated and unused |
| ECR images | storage cost over time |

## Cleanup flow

The expected cleanup flow is:

```text
remove application resources
-> remove observability resources
-> delete application namespaces
-> terraform destroy
-> run cleanup verification script
```

Application cleanup:

```bash
make helm-uninstall
make observability-uninstall
kubectl delete namespace incident-api --ignore-not-found
kubectl delete namespace observability --ignore-not-found
```

AWS cleanup:

```bash
make tf-destroy
```

Post-destroy verification:

```bash
./scripts/check-aws-cleanup.sh
```

## Security and governance impact

V8 improves the platform operating model by making cleanup auditable and
repeatable.

It reinforces these principles:

- cloud resources are created intentionally
- cloud resources are destroyed intentionally
- deployment workflows do not create infrastructure
- EKS is not left running without a reason
- public endpoints are avoided by default
- cleanup verification is part of the workflow

## Validation

The cleanup verification script was tested while the EKS cluster was still
active.

Expected result:

```text
[FAIL] EKS cluster still exists: aws-eks-platform-golden-path-dev-eks
```

This confirms that the script fails correctly when cleanup is incomplete.

The script should be run again after `make tf-destroy` to validate the final
cleanup state.

## Out of scope

V8 does not add:

- AWS Budget resources
- automated cost alerts
- Cost Explorer reports
- ECR lifecycle policies
- scheduled cleanup automation
- multi-account FinOps reporting

These remain future FinOps enhancements.

## Final outcome

V8 adds a repeatable cost-control loop:

```text
create AWS environment
-> validate platform capability
-> destroy AWS environment
-> verify cleanup
-> document remaining resources if any
```
