# Release v6.0.0 - Controlled Release and Rollback Strategy

Release date: 2026-06-01

V6 adds controlled release and rollback operations to the AWS EKS Platform
Golden Path.

The goal of this release is to make application delivery safer by supporting
explicit image tags and manual Helm rollback.

## Highlights

V6 adds:

- optional image tag input in the deployment workflow
- safe fallback to the current commit SHA
- dedicated manual rollback workflow
- GitHub Environment approval for rollback
- Helm history validation
- Helm rollback validation
- rollout status after rollback
- in-cluster smoke test after rollback

## Deploy workflow update

The `Deploy Incident API` workflow now accepts:

```text
image_tag
```

When the field is empty, the workflow defaults to:

```text
github.sha
```

This preserves the original traceable deployment model.

When the field is provided, the workflow uses the provided tag value for the
image build, push, and Helm deployment.

## Rollback workflow

V6 adds:

```text
.github/workflows/rollback-incident-api.yml
```

The workflow is triggered manually with:

```text
workflow_dispatch
```

Required input:

```text
revision
```

The workflow performs:

```text
GitHub Environment dev approval
-> GitHub OIDC authentication
-> EKS cluster validation
-> kubeconfig update
-> helm history
-> helm rollback
-> rollout status
-> in-cluster smoke test
```

## Security boundaries

The rollback workflow does not run Terraform.

It does not create or destroy AWS infrastructure.

It does not build or push Docker images.

It uses the existing GitHub Actions deploy role and the existing
namespace-scoped Kubernetes RBAC model.

## Validation

A new deployment revision was created with the updated deploy workflow.

The rollback workflow was then tested against an earlier Helm revision.

Final Helm history confirmed:

```text
revision 1 -> superseded
revision 2 -> superseded
revision 3 -> deployed, Rollback to 1
```

This confirms that Helm rollback works through GitHub Actions and produces a
new deployed revision.

## Operational outcome

V6 adds a basic release safety mechanism:

```text
deploy
-> detect issue
-> select previous Helm revision
-> manual rollback workflow
-> rollout validation
-> smoke test
```

This is intentionally simple and compatible with the existing cost-aware
platform model.

## Out of scope

V6 does not include:

- canary deployment
- blue-green deployment
- progressive traffic shifting
- automated rollback from alerts
- multi-environment promotion
- deploy-existing-image-only workflow

These remain future enhancements.

## Final outcome

V6 validates controlled release operations for the Incident API:

```text
explicit image tag support
-> Helm release history
-> manual rollback
-> rollout validation
-> smoke test
```
