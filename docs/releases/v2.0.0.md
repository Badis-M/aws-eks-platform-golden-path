# Release v2.0.0 - Observability

Release date: 2026-05-27

V2 adds Kubernetes observability to the AWS EKS Platform Golden Path.

The goal of this release is to validate that the application exposes useful
metrics and that the EKS cluster can collect, query, and visualize them with
Prometheus and Grafana.

## Highlights

V2 validates the observability layer:

- kube-prometheus-stack
- Prometheus Operator
- Prometheus
- Grafana
- kube-state-metrics
- node-exporter
- ServiceMonitor discovery
- FastAPI metrics exposed on `/metrics`
- PromQL queries
- Grafana Explore visualization

## Application metrics

The Incident API exposes Prometheus-compatible metrics on:

```text
/metrics
```

Validated metrics include:

```text
incident_api_info
http_requests_total
```

The application records HTTP requests by:

- method
- path
- status code

## Observability stack

The observability stack is deployed with Helm through kube-prometheus-stack.

It runs in the namespace:

```text
observability
```

The application runs in:

```text
incident-api
```

This keeps application resources and observability tooling separated.

## ServiceMonitor design

The Helm chart supports ServiceMonitor creation, but ServiceMonitor is
disabled by default.

This prevents deployment failures when Prometheus Operator CRDs are not
installed.

Observability mode is enabled through:

```text
observability/incident-api-observability-values.yaml
```

## Validated observability path

V2 validates the full metrics flow:

```text
FastAPI /metrics
-> ServiceMonitor
-> Prometheus scrape
-> PromQL query
-> Grafana Explore visualization
```

## PromQL validation

Validated queries include:

```promql
incident_api_info
```

```promql
http_requests_total
```

```promql
sum by (path) (
  rate(http_requests_total{namespace="incident-api",path=~"/health|/ready|/metrics"}[5m])
)
```

## Access model

Prometheus and Grafana are not exposed publicly.

Access is done through port-forwarding:

```text
ClusterIP
-> kubectl port-forward
-> local browser
```

This avoids public exposure, ingress complexity, and unnecessary load balancer
cost.

## Validation summary

V2 was validated with:

```bash
make observability-install
make helm-deploy-observability
make observability-check
kubectl get servicemonitor -n incident-api
```

Grafana Explore validated the application metrics after Prometheus scraping.

## Security and cost impact

V2 keeps observability private and cost-aware:

- no public Grafana endpoint
- no public Prometheus endpoint
- no LoadBalancer for observability access
- no public ingress
- ServiceMonitor enabled only when required

## Out of scope

V2 does not include:

- alert rules
- Alertmanager routing
- Grafana dashboards as code
- public ingress
- TLS termination
- long-term metrics storage

These are candidates for future SRE-focused releases.
